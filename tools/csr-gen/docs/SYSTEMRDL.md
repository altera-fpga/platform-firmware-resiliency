# SystemRDL support

`csr-gen` reads and writes [SystemRDL 2.0](http://accellera.org/downloads/standards/systemrdl)
addrmaps for CSR register blocks. Markdown remains the authoritative specification;
SystemRDL is an interchange format for migration and tool integration.

## Scope

| Feature | Supported |
| --- | --- |
| Top-level shape | Exactly one `addrmap` per file |
| Register width | 32-bit (`regwidth = 32`) |
| Addresses | Block-local byte offsets from `0` |
| Fields | Explicit `[msb:lsb]` placement and reset values |
| Access keys | All csr-gen Markdown access keywords |
| External registers | `external reg` instances |
| Address ranges | Native register arrays (`NAME[N] @ base += 4`) on export; import accepts arrays and legacy `csr_gen_address_end` |
| Third-party import | Flat addrmap registers without csr-gen UDPs (access inferred from `sw` / `onread` / `onwrite`) |
| Hierarchy import | Nested `regfile` and single-IP nested `addrmap` instances flattened into one bank; multi-peripheral files require `--systemrdl-addrmap` |
| Round-trip | Files generated by csr-gen (golden `expected.rdl`) |

Not supported today:

- `mem` and `signal` components
- Multiple top-level addrmaps per file
- Non-32-bit `regwidth`
- Importing multiple nested addrmaps into one merged model (use `--systemrdl-addrmap` per peripheral)

## Hierarchy import policy

csr-gen maps one Markdown `##` section to one flat `RegisterModel` and one RTL
block. Markdown `###` subsections merge tables into that **same** address space;
they are not separate peripherals.

| SystemRDL construct | Import strategy |
| --- | --- |
| `regfile` instance | **Flatten** into the current bank: absolute offset = instance `@` address + register offset; add a name prefix only when register names collide |
| Nested `addrmap` (single logical IP / sub-range of one peripheral) | **Flatten** into the same bank (same rules as regfiles) |
| Nested `addrmap` (multiple independent peripherals in one file) | **Separate banks**: one Markdown `##` section per selected addrmap instance, not one merged model |
| `mem`, `signal` | Remain unsupported until explicitly designed |

Multi-peripheral migration mirrors IP-XACT: import one subtree at a time with
`--systemrdl-addrmap` to select a nested addrmap instance, similar to
`--ipxact-address-block`. Do **not** map every regfile to a Markdown
`###` subsection — subsections are for table layout inside one bank, not a
general SystemRDL hierarchy model.

### Hierarchical fixture expectations

| Fixture | Expected result |
| --- | --- |
| `tests/testdata/systemrdl/hierarchical_regfile.rdl` | Import succeeds; regfile registers use absolute addresses |
| `tests/testdata/systemrdl/hierarchical_nested_addrmap.rdl` | Import succeeds; nested addrmap registers flattened with absolute addresses |
| `tests/testdata/systemrdl/hierarchical_multi_peripheral.rdl` | Import rejected without `--systemrdl-addrmap`; succeeds with selector |
| Accellera Leon2 / SATA-style maps | Import one peripheral at a time via `--systemrdl-addrmap`; full-tree import not supported |
| Files containing `mem` or `signal` | Rejected |

## User-defined properties

csr-gen exports one UDP declaration in generated files:

| UDP | Component | Purpose |
| --- | --- | --- |
| `csr_gen_access` | `field` | Preserve csr-gen access keywords (`none`, `rw1c`, …) |

Import still accepts legacy files that declare `csr_gen_address_end` on ranged registers.

The addrmap `desc` property stores the Markdown section heading (for example
`CSR Registers`). The addrmap instance name is derived from that heading.

## Field access mapping

Markdown `Access` values map to SystemRDL field properties:

| Markdown | SystemRDL field properties |
| --- | --- |
| `none` | `sw = r; hw = r;` plus `csr_gen_access = "none"` |
| `ro` | `sw = r; hw = r;` |
| `rc` | `sw = r; onread = rclr; hw = r;` |
| `rw` | `sw = rw; hw = rw;` |
| `wo` | `sw = w; hw = r;` |
| `r0w1c` | `sw = rw; onread = rclr; onwrite = woset; hw = rw;` |
| `rw1s` | `sw = rw; onwrite = woset; hw = rw;` |
| `rw1c` | `sw = rw; onwrite = woclr; hw = rw;` |
| `rw0c` | `sw = rw; onwrite = wzc; hw = rw;` |

Import prefers `csr_gen_access` when present; otherwise it infers csr-gen access
from `sw`, `onread`, and `onwrite`.

## Validation strategy

1. **Semantic truth:** `RegisterModel` round-trips and golden `expected.rdl` files
   under `specs/golden/`.
2. **Language validity:** `systemrdl-compiler` `compile_file()` +
   `elaborate()` on goldens and writer test output (`tests/unittests/test_systemrdl_elaborate.py`).
3. **PeakRDL smoke tests (opt-in):** `peakrdl html` and `peakrdl regblock` on golden
   `expected.rdl`; `peakrdl dump` on golden `expected.xml` (`tests/end2end/eda/peakrdl/`
   via `make test-end2end-eda`).
4. **Accellera import smoke tests (opt-in):** selected SystemRDL 1.0 spec examples
   import to Markdown (`tests/end2end/eda/accellera/` via `make test-end2end-eda`).

IP-XACT export naming and PeakRDL-ipxact validation are documented in [`IPXACT.md`](IPXACT.md).

## CLI examples

```sh
# Markdown → SystemRDL
csr-gen generate \
  --input-file specs/golden/example-device/regs.md \
  --input-format markdown \
  --markdown-section "CSR Registers" \
  --output-file work/example.rdl \
  --output-format systemrdl

# SystemRDL → Markdown
csr-gen generate \
  --input-file specs/golden/example-device/expected.rdl \
  --input-format systemrdl \
  --output-file work/from-rdl.md \
  --output-format markdown \
  --markdown-section "CSR Registers"

# Multi-peripheral SystemRDL → one peripheral
csr-gen generate \
  --input-file work/soc.rdl \
  --input-format systemrdl \
  --systemrdl-addrmap uart_inst \
  --output-file work/uart.md \
  --output-format markdown
```

When importing SystemRDL, `--markdown-section` is optional if the addrmap `desc`
property is present.

## Development dependency

Install test dependencies from `requirements.txt` (includes `systemrdl-compiler`).
PeakRDL smoke tests additionally require `requirements-eda.txt` (installed by
`make test-end2end-eda`). The runtime wheel does not require SystemRDL packages;
import reports a clear error when `systemrdl-compiler` is missing.

Run SystemRDL unit and elaboration tests:

```sh
make test-unittests
make test-end2end-eda
```

Golden oracles: `specs/golden/<case>/expected.rdl`.
